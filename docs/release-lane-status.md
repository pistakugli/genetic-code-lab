benchmark command, not a hidden synthetic fixture and not a fitted surrogate.

under `graphGate.pass && hardeningGate.pass`, and Stage-I hardening over

artifact was regenerated through the explicit CUDA runtime lane and records
`model.device = cuda`. This does not promote attention-head/path recovery or
arbitrary LLM understanding.

benchmark command. Its current artifact reports 50 valid factual prompts, 50

## Artifact Collision Rules

- Patched release benchmark scripts separate smoke/wide/hybrid outputs under `benchmarks/release/`.
- Root-level `benchmarks/*` artifacts remain legacy mixed-use files and may have been overwritten by older smoke, wide, or scratch runs.
- `release:gate` rewrites multiple isolated release benchmark artifacts and manifests.
- Never infer lane status from a filename alone; use the command, run date, and `docs/evidence-map.md`.

## Current Release Rule

Default threshold policy is code, not documentation: `npm run verify:default-threshold-policy` runs the engine with threshold env flags removed and fails unless the runtime uses `compose-adaptive-duel`, executes adaptive-duel decisions, and does not fall back to static paired-witness compose.

`release:gate` runs that invariant before benchmark gates, then runs the Santa Fe replay verifier and positive-use-case calibration that proves guarded promotion is actually useful.
