# Real Qwen2.5-0.5B SwiGLU Pilot: Oracle-Only Recovery Attempt

Date: 2026-11-01  
Status: real-module capture and post-hoc evaluation verified; hidden-structure recovery not achieved

## Result in brief

The original adaptive student-distillation baseline queried the real
`model.layers.0.mlp` oracle with 73,728 generated points but did not recover
useful function or structure. A new full-width split-continuation run then used
the exact bias-free SwiGLU family, 1,111 natural recovery observations, and
another 73,728 oracle points. The solver saw neither model weights nor hooks
nor the teacher intermediate width. It selected a 2,048-component student from
measurements; that width is not an estimate of Qwen's 4,864 hidden components.

The new run is measurable progress, **not successful hidden-structure
recovery**. On 549 prompt-disjoint natural functional-evaluation vectors, its
relative error is `0.5581` and NMSE is `0.3567`. Distributional NMSE on 537
independent natural vectors is `0.3443`; generated oracle-validation NMSE is
`0.5445`. Post-hoc structural comparison finds median absolute gate cosine
`0.1371` and zero student gates at cosine `0.99`. Host-process `VmHWM` is
`3,098,435,584` bytes. A race-clean 50-ms process-tree monitor measured peak
parent-plus-oracle PSS of `3,793,379,328` bytes (`3.53 GiB`) across 457 samples,
below the 4-GiB limit; the monitor exited without an exception. Functional
fidelity remains above the stated `0.1` NMSE target, and structural recovery
is not achieved.

An optional oracle-JVP supervision branch was then implemented and tested on
the exact SwiGLU student. Across three full-width Qwen runs, it did not improve
on the output-only baseline: the best JVP run had functional/distributional
NMSE `0.4052`/`0.3919` versus `0.3567`/`0.3443` without JVP, and all JVP runs
had zero gate matches at cosine `0.99`. A lower JVP weight worsened the scores
further. This is measured negative evidence, not a recovery result.

## Access modes and truth boundary

- Activation collection is **instrumented**: forward hooks record the real
  MLP input/output tensors, token IDs, positions, prompt IDs, and prompt hashes.
- Generated probes use the **opaque eval-only full-module oracle**. Its client
  receives the input/output dimensions but not model, layer, device, unit count,
  or selected-unit metadata. The original 32-probe smoke used 32 of a
  128-query budget; the recovery run made 73,728 full-vector oracle queries.
- The adaptive student solver received natural recovery observations and an
  opaque callable only. Its report records oracle-only access and no teacher
  weights, hooks, hidden-unit count, or component identities.
- The independent verifier reloads the local checkpoint **after capture** and
  compares saved data with full-model inference and direct MLP evaluation. The
  independent evaluator also reloads the checkpoint after the student artifact
  is frozen; both are post-hoc white-box witnesses, not solver input.

## Exact module and cubic workspace cause

The installed Qwen2 module computes

```text
f(x) = W_down ( SiLU(W_gate x) elementwise-multiplied-by (W_up x) )
```

with no projection biases. At 896 input/output and 4,864 intermediate units,
the three matrices contain `3 * 896 * 4864 = 13,074,432` scalar parameters.
Hidden-unit permutation is a symmetry; each up-projection row and matching
down-projection column also admit a nonzero reciprocal scaling symmetry.
Gate scaling is not a symmetry of SiLU.

The old 308.4-PiB guard is the dense cubic regression implementation, not a
lower bound on recovery storage. With `n=896`, its cubic monomial count is
`M = C(n+2,3) = 120,288,896`; the solver sets `R = ceil(3M) = 360,866,688`
directions. The float64 design alone is `R*M*8 =
347,266,044,021,571,584` bytes; the directions add `R*n*8 =
2,586,692,419,584` bytes. The exact combined estimate is
`347,268,630,713,991,168` bytes, or `308.4365 PiB` (`323,419,115.24 GiB`).
Since `M` and `R` both scale as `n^3` for a fixed direction multiple, the
explicit `R x M` float64 design scales as `O(n^6)`; the `R x n` direction
tensor scales as `O(n^4)`. The guard's `minimumWorkspaceBytes` is exactly the
sum of these two tensors; it is not a peak-RAM prediction and excludes other
temporary and library allocations. No such allocation was attempted: the
guard rejects the design before oracle calls. This memory is required by the
dense least-squares implementation, not by the black-box recovery objective.

## Adaptive student formulation and query record

The implemented alternative parameterizes a bias-free student as
`W_down' (SiLU(W_gate' x) .* (W_up' x))`. Candidate widths grow geometrically
from 1 through a generic cap of 8,192; no candidate is initialized from the
teacher's hidden width. The training set combines the 42 captured natural
recovery vectors with generated oracle observations. Generated inputs use
coordinate RMS estimates from those observations and four radial shells.
Held-out oracle probes score candidate widths by normalized MSE. Additional
query batches go to the validation shell with the largest residual. Solver
training data remains CPU-resident and is transferred in mini-batches; the
oracle request path streams batches of at most 2,048 points rather than
materializing a cubic tensor.

## Split-continuation follow-up

### Formulation and exact versus approximate steps

The student keeps the target family
`f(x) = sum_i d_i * SiLU(g_i dot x) * (u_i dot x)`. For any component,
duplicating `(g_i, u_i, d_i)` into two identical gate/up pairs with output
columns `d_i/2` is an exact identity. The implementation then adds opposite
perturbations to the duplicated gate/up parameters and optimizes them; that
perturbed step is approximate and no longer preserves the function exactly.
Permutation and reciprocal up/down scaling remain legitimate symmetries; gate
scaling is not.

For fixed gate/up parameters, the hidden feature matrix is
`H[j,i] = SiLU(g_i dot x_j) * (u_i dot x_j)`. The down projection is updated
by streamed accumulation of `H.T @ H` and `H.T @ Y`, followed by a ridge
regularized Cholesky solve. This avoids the cubic design's combinatorial
expansion. Its projection workspace is `O(k^2 + k*m)` for student width `k`
and output width `m`, and feature computation is blocked; it is not constant
memory and the nonlinear gate/up optimization remains non-convex.

The natural-input probe covariance uses mean-preserving shrinkage and four
radial shells (`0.45`, `0.75`, `1.0`, `1.4`). Training batches reserve 75% of
their natural-sample portion for captured recovery observations. Candidate
student widths grow geometrically to 8,192 and are selected on held-out oracle
NMSE. The solver gets no teacher count, component identities, weights, hooks,
or hidden intermediate activations.

The expanded prompt-disjoint capture contains 1,111 recovery, 549 functional,
39 structural, and 537 distributional natural samples. The independent
evaluator validates the copied additional-prompt sources against their hashes
and replays the target outputs. The 8,192 generated validation probes remain a
separate dataset from the natural activations and training queries.

### Query, runtime, and resource accounting

- 32,768 initial training + 8,192 validation + 32,768 adaptively selected
  shell probes = **73,728 oracle points**, exactly the configured budget;
  1,111 captured natural recovery observations were reused.
- The student selected 2,048 components with validation NMSE `0.5445`; its
  best candidate score is not a recovery-accuracy claim.
- Fitting took `44.46 s`. On an NVIDIA GeForce RTX 3070 with PyTorch
  `2.10.0+cu128`, solver peak allocated VRAM was `1,506,938,368` bytes and
  solver-sampled whole-device use peaked at `5,063,376,896` bytes.
- Parent `VmHWM` was `3,098,435,584` bytes (`2.89 GiB`); the 50-ms
  process-tree monitor sampled parent and oracle-child PSS together and
  peaked at `3,793,379,328` bytes (`3.53 GiB`) across 457 samples. The
  oracle child's own `VmHWM` was `3,710,382,080` bytes. These measurements
  remain below the 4-GiB host budget; the combined PSS is a sampled peak, not
  a kernel-enforced cgroup peak.
- A separate 1-second `nvidia-smi` sampler captured 79 rows with mean GPU
  utilization `39.90%`, maximum `99%`, mean memory utilization `27.04%`,
  and sampled device-memory maximum `5,063,573,504` bytes. The raw CSV and
  summary are preserved above.
- The older `resource.getrusage(...).ru_maxrss * 1024` field is not a reliable

  `116,498,432` bytes from `/proc/self/status:VmHWM` but an `ru_maxrss`-derived

  `VmHWM`; the older baseline's 8.6-GB number is therefore retained only as a
  legacy, invalid measurement, not evidence that the baseline exceeded 4 GiB.

## Oracle-JVP supervision pilot

The continuation solver now optionally adds a directional-derivative loss.
For each sampled unit direction `v`, the opaque oracle supplies the central
difference
`[f(x + eps v) - f(x - eps v)] / (2 eps)`; the student computes its SwiGLU
directional derivative analytically. The target is a finite-difference
approximation (not an exact oracle derivative), while the student derivative
formula is analytic. The paired endpoints are also ordinary output-training
observations: the JVP pairs do not consume additional queries beyond the
configured 73,728-point budget. The default derivative weight remains zero,
so existing output-only runs are unchanged.

On the two small exact-SwiGLU synthetic cases, weight `0.05` and a `0.25`
paired-query fraction improved held-out NMSE: `6 -> 4` changed `0.539` to
`0.252`; `8 -> 5` changed `0.635` to `0.610`. This synthetic gain did not
transfer to Qwen. A separate synthetic run at weight `0.2` improved the
`6 -> 4` case (`0.539` to `0.322`) but regressed the `8 -> 5` case
(`0.635` to `0.672`), so the small-case effect is also parameter-sensitive.
The independent post-hoc Qwen comparison is:

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Output-only baseline | 0 / 0 | 2,048 | 0 | 0.3567 | 0.3443 | 0.5445 | 0.1371 | 0 |
| Full initial-training pairing | 0.05 / all 32,768 initial points | 256 | 16,384 (32,768) | 0.4911 | 0.4804 | 0.6902 | 0.1331 | 0 |

observations. The low-weight run took `60.36 s`, used `1,508,773,888` bytes

Its sampled parent-plus-oracle PSS peak was `4,104,059,904` bytes (`3.82

at `5,088,870,400` bytes. A separate GPU sampler recorded 153 samples during

The low-weight solver/evaluator linkage is SHA-bound; raw observations,
reconstruction, report, and GPU samples are preserved. The JVP validation
score and component metrics are not evidence of teacher-width inference or
structural identifiability. No measured result establishes why the derivative
objective underperforms on Qwen; that causal question remains open.

## Remaining mathematical and resource limits

The cubic guard remains intact as a regression and still rejects 896 dimensions
before allocation. The student route avoids that design, but the executed
continuation student is not accurate enough to recover the target. Structural
identifiability of all 4,864 components from finite oracle observations remains
unknown; these runs neither prove it nor prove impossibility.

## Next gate

Develop a materially different identification objective rather than increasing
the JVP loss: the tested derivative-supervised continuation variants all
underperform the output-only Qwen baseline and do not recover structure. Preserve
the full 896-dimensional input/output domain and the oracle-only boundary. The
next recovery gate must retain the synthetic exact-recovery regression, stay
below 4 GiB host RSS, achieve held-out natural NMSE below `0.1`, and demonstrate
nontrivial one-to-one structural alignment modulo permutation and reciprocal
up/down scaling. The current continuation and JVP routes pass full-width
execution and query accounting, but not functional, distributional, or
structural recovery.

## Amplitude-polarity trajectory experiment

The next experiment measured 96 unit directions from the expanded real-Qwen
recovery capture: 32 observed natural activations, 32 seeded two-activation
combinations, and 32 independent Gaussian directions. Each direction was
queried at 12 amplitudes from `0.25` through `512` under both signs, for
exactly 2,304 opaque full-module oracle points. Direction sources, token
positions, prompt hashes, coefficients, exact query inputs, outputs, and
normalized responses are retained in the raw artifact. The probe report
records `solverAccess=oracle-only`; the opaque oracle did not disclose a unit
count or truth capability.

For the bias-free module

```text
f(x) = D (SiLU(Gx) ⊙ Ux)
```

the componentwise large-amplitude limits are

```text
P(u) = D Σᵢ max((Gu)ᵢ, 0) (Uu)ᵢ
N(u) = D Σᵢ min((Gu)ᵢ, 0) (Uu)ᵢ
```

and satisfy the exact identity `P(-u)=N(u)`. Thus polarity reversal in this
limit is not a second independent response family; it exchanges the direction.
The finite-amplitude trajectories could still carry additional information, so
the probe retained every amplitude rather than replacing them with extrapolated
limits.

### Measurements and verdict

At the final two amplitude transitions, **none** of the 96 directions met the
predeclared 1% relative-change stability criterion for both polarities. Median
relative changes were 3.05% positive / 2.76% negative; the pooled transition
P95 values were 7.99% / 7.72%. Therefore the sampled trajectories had not
reached the declared stable regime at amplitude 512.

An independent post-hoc reload replayed the recorded inputs through the local
Qwen module. Maximum per-sample relative L2 replay error was
`7.04e-7` (threshold `5e-6`); the maximum absolute difference was
`0.00146484375` at the largest amplitudes, where outputs are much larger and
absolute-only comparison is misleading. The evaluator's teacher-weight read
was post-hoc and did not feed the probe or any solver.

At amplitude 512, median relative error against the exact weight-derived limit
was 0.47%/0.73% (negative/positive) for natural directions, 0.65%/0.68% for
natural combinations, and 1.34%/1.37% for independent Gaussian directions.
These are post-hoc limit comparisons, not evidence that the solver could
recover those limits or the factors that produce them.

Post-hoc per-component response signatures were not an oracle-only
decomposition. On natural directions, nearest-component absolute cosine before
the down projection had median 0.832 positive and 0.773 negative, with 414
and 49 components respectively having a nearest cosine at least 0.99. After
the down projection those medians were 0.072 and 0.064, with zero such pairs
at 0.99. On the 32 independent Gaussian directions, post-projection median
nearest cosines were 0.059 positive and 0.059 negative. Those signatures were
calculated using teacher weights only by the independent evaluator; the oracle
returns the sum of components, not these individual signatures. Consequently,
they do not establish that polarity makes hidden components separable from
oracle observations.

The probe took 6.48 seconds. Peak parent VmHWM was 690,233,344 bytes, oracle
child VmHWM was 3,707,174,912 bytes, sampled combined parent/child PSS peaked
at 1,410,061,312 bytes, and device-wide GPU use peaked at 3,032,481,792 bytes
(the latter includes other GPU processes). The post-hoc evaluator took 3.21
seconds; its process VmHWM was 3,850,379,264 bytes and CUDA allocator peak was
2,367,136,256 bytes. Probe timing and memory are direct measurements, not
extrapolations.

**Verdict:** this experiment did not justify an amplitude-response recovery
solver. It falsified the predeclared claim that both polarity trajectories
stabilize by amplitude 512 for the tested directions. It did not falsify the
exact polarity identity or prove that no larger amplitude stabilizes; larger
amplitudes were not queried. It also did not show that an oracle-only solver
can identify any teacher components from the measured summed outputs.

The next distinct experimental direction is **adaptive activation-boundary
localization**, not another amplitude sweep: along oracle-selected input lines,
use only full-vector function evaluations to bracket gate transition regions
from changes in line-response shape, then test on synthetic exact-SwiGLU
teachers whether the localized boundary constraints isolate a component
without teacher labels. Only proceed to a real Qwen pilot if the synthetic
controls show component-level identifiability under the output projection.
This tests local transition geometry rather than large-amplitude limits and
does not reuse polarity/asymptote extrapolation.

## Synthetic hidden-structure observability study (2026-11-01)

The next experiment compared three non-derivative query organizations before
spending any more queries on real Qwen. The target synthetic family was the
complete bias-free SwiGLU function

```text
f(x) = Σᵢ dᵢ SiLU(gᵢᵀx) (uᵢᵀx)
```

with full-vector outputs. Each measurement used only an oracle callable, public
input/output dimensions, a query budget, and a seed. The measurement function
received neither teacher arrays nor hidden width nor component labels. The
teacher was retained by the synthetic oracle and used by a separate
post-measurement evaluator; this is an API-level boundary, not a claim of
process-level isolation.

### Hypotheses and signatures

1. **Coordinate erasure.** Draw `z ~ N(0,I)` and independent
   `mⱼ ~ Bernoulli(p)`, then query `x = (m ⊙ z)/√p` for `p ∈ {0.25, 0.5,
   0.75}`. This preserves `E[xxᵀ]=I` but changes coordinate-wise higher
   moments (`E[xⱼ⁴]=3/p`) and could change which gate/up projections are
   co-excited at a fixed query count. The predicted signature was reduced
   nearest-component cosine after the output projection on held-out
   mask-distributed inputs. It should fail when projections are dense and
   output mixing dominates, or when erasure only removes signal.

2. **Complementary coordinate blocks.** Partition input coordinates into
   `K ≤ 4` blocks, choose one block uniformly, and query
   `x = √K P_b z`. The pooled covariance remains `I`; each query, however,
   excites only one coordinate subspace. Components with unequal block energy
   could therefore acquire distinct response fingerprints. It should fail
   when dense components distribute similarly across blocks or their
   projected responses remain collinear. The held-out check also requires
   nonzero output response energy in every block.

3. **Activation environments.** Match the input dimension and query count
   while interleaving sparse `20%`-coordinate inputs, dense Gaussian inputs,
   and Gaussian inputs with a randomized covariance spectrum from `1` to
   `0.05`. Sparse and dense environments have identity covariance but
   different higher moments; the correlated environment changes covariance
   directions. A signature should improve on the pooled held-out set and in
   both sparse and correlated subcohorts. This should fail if an environment
   only rescales shared responses, suppresses weak components, or cannot
   preserve a common component ordering.

For evaluator diagnostics, component `i` has response
`cᵢ(x)=dᵢ SiLU(gᵢᵀx)(uᵢᵀx)`. The evaluator concatenates these per-query
vectors over held-out inputs and compares the median and P95 nearest
**absolute** pairwise cosine before and after the output projection. That
requires teacher weights and is expressly not an oracle-only feature. A
positive change in this diagnostic can motivate further synthetic work, but
cannot by itself authorize a real-model pilot or prove component recovery.

### Synthetic controls and results

Three teacher seeds varied `(input, hidden, output)` dimensions over
`(8,6,5)`, `(10,8,6)`, and `(14,12,8)`. Each seed covered generic, nearly
overlapping, weak-component, rank-1 output, rank-3 output, duplicate-gate,
and zero-down-column teachers. Every teacher/protocol used 384 observations
(256 training, 128 held out), for `21 × 4 × 384 = 32,256` measured synthetic
oracle points. The held-out outputs replayed exactly in the recorded run;
the independent verifier recomputed them from the evaluator-only teacher.
All 84 compressed raw files retain exact input/output arrays, their
protocol/seed association, an output-readout matrix, derived readouts, and
SHA-256 hashes.

The preregistered screening threshold required at least two of three seeds to
improve **both** median nearest cosine by at least `0.10` and P95 by at least
`0.05` versus query-matched IID. For complementary blocks every held-out
block also needed nonzero output energy; activation environments additionally
needed positive median improvement in both sparse and correlated subcohorts.
No protocol passed:

| Protocol | Median improvement by seed 17 / 29 / 43 | P95 improvement by seed 17 / 29 / 43 | Seeds passing |
|---|---:|---:|---:|
| Coordinate erasure | -0.0731 / 0.0059 / 0.0156 | -0.0394 / 0.1025 / -0.0424 | 0/3 |
| Complementary blocks | -0.0838 / 0.0542 / -0.0240 | -0.0661 / 0.1053 / -0.1513 | 0/3 |
| Activation environments | 0.0287 / 0.0442 / -0.0314 | -0.0426 / 0.0011 / -0.0790 | 0/3 |

On the three generic teachers, evaluator-only median nearest cosine before
the output projection ranged from `0.869` to `0.946`; after projection it
ranged from `0.110` to `0.148`. This reproduces the projection-interference
pattern in these small synthetic cases only. The new query organizations did
not produce repeatable improvement, and none exposed a component-level
oracle-only decomposition.

The output-readout control is exact data processing: for any matrix `A`, a
readout `Ay` is determined by the already observed full output `y`; it adds
zero oracle points and cannot add information. The saved derived readouts
replay with maximum absolute error `0.0`.

The evaluator also confirms exact non-uniqueness: permutation and reciprocal
up/down scaling preserve the function; when two gate rows are equal,
`D_group R` and `R⁻¹ U_group` preserve the shared-gate response for every
invertible `R`; and a zero down column can be added or removed without
changing any output. These establish equivalence classes for those cases,
not generic uniqueness or generic impossibility. Whether a generic full-rank
SwiGLU representation is identifiable modulo these symmetries remains
unknown.

### Decision, resources, and artifacts

The post-hoc fingerprint screen did not pass, so no real-model query was
spent. More importantly, even if it had passed, the fingerprints require
teacher weights and no oracle-only recovery solver was implemented; that
diagnostic alone is insufficient to authorize a Qwen campaign. Functional
replay of the synthetic oracle is verified, but hidden-unit recovery,
hidden-width inference, and real-Qwen generalization are not established.

The final NumPy-only run took `0.36 s` wall time and peaked at `42,168 KiB` process
RSS (`/usr/bin/time -v`). It did not use a GPU; VRAM was not measured because
the experiment used no GPU operations. These resource figures are for this
small synthetic study, not a full-width Qwen solver.

**Next gate:** test a distinct observable, the reachable output-subspace rank.
For `y(x)=D h(x)`, every observed output lies in `col(D)`, so the rank of a
matrix of outputs is a query-derived lower bound on `rank(D)`. On controlled
rank-1/rank-3 teachers it may identify the output rank, but it cannot reveal
hidden width when `D` is full row rank, nor identify individual gate/up
factors. Validate the rank estimate and its sample-count/noise failure modes
on synthetic raw observations before considering another real-model pilot.
