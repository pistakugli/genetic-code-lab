# GCL capability matrix

**Evidence cutoff:** 2026-10-30. See [the full prior-art audit and bibliography](GCL_PRIOR_ART_AUDIT.md) for source descriptions and primary links. “Established” means the capability has credible implementation/result evidence in GCL; it does not mean broad generalization.

| Capability | GCL implementation and current evidence | Existing public methods | Exact difference / defensible status |
|---|---|---|---|
| Internal model reading | [`gpt2_internal_trace.py`](../../tools/llm_reader/gpt2_internal_trace.py) uses local GPT-2 weights and hooks to record embeddings, layer states, attention/head writes, MLP/neuron values, norm and logits. Adapter registry supports other families for selected path operations. | TransformerLens exposes cached activations and editing; HuggingFace/PyTorch instrumentation is standard research practice. | **Engineering integration, not unique.** GCL supplies its own trace/archive/report/verifier pipeline. This access is instrumented/white-box, not oracle-only. |
| Residual tracing/reconstruction | Residual addition is checked by the trace. Five-case report records error `0`; all-50 autoregressive report records a maximum around `3.05e-5`. | Transformer instrumentation and residual-stream decomposition are standard in mechanistic interpretability; TransformerLens is a prominent toolkit. | **Reproducible implementation.** Do not call all-50 reconstruction bitwise exact; do not equate exact arithmetic bookkeeping with full network reconstruction. |
| Attention/MLP analysis | Captures attention output and per-head projected residual write, MLP preactivation/activation/output, and per-neuron local first-order attribution. | ROME, Knowledge Neurons, GPT-2 IOI circuit, ACDC/EAP and TransformerLens inspect heads, MLPs or neurons. | **Established concepts with GCL integration.** First-order attribution is an approximation, not independent causal proof or neuron semantics. The trace does not include attention probability matrices. |
| Factual localization | Frozen ordered-path finder searches constrained attention/MLP candidates on factual prompts; 50-fact GPT-2 artifact. | ROME causal tracing/ROME editing; Knowledge Neurons; many causal-localization papers. | **Adaptation/integration.** GCL's frozen path type and exact dataset differ; factual localization itself is not new. |
| Circuit discovery | Constrained ordered-path sweep with selected nodes, control paths, fallback/rescue selection and fixed score logic. | ACDC automates task-circuit edge selection; EAP ranks edges via gradient approximations; other automated circuit localization methods exist. | **Potential implementation contribution only.** GCL's path sweep is not a general graph algorithm; ACDC/EAP are prior art for automated localization. |
| Causal intervention | Head/neuron/group ablation, path restoration, donor-path activation patch, structural random controls. | Activation/path patching, interchange interventions, ROME causal tracing, mediation and causal scrubbing. | **Established operators.** GCL applies them in its own path/prompt protocol; it does not introduce the general intervention class. |
| Autoregressive tracing | All-50 GPT-2 run records 600 token predictions, exact baseline contexts, greedy IDs and layerwise traces; 50/50 replay. | Mechanistic tools can cache/edit activations per forward pass; prior circuit papers test output tokens and interventions. | **Reproducible evaluation integration.** GCL's token-by-token dataset may be valuable; this capability alone is not methodologically unique. Run is capped at 12 generated tokens and not all traces imply an answer-complete continuation. |
| Actual-token explanations | Machine-readable WHAT/HOW/WHY/WHAT ELSE/LIMITATIONS evidence generated for actual baseline greedy tokens. | Anthropic attribution graphs and HyVE explain already-localized computations; OpenAI's neuron-explanation research page is relevant but was not retrievable for detailed checking here. | **Useful integration, not semantic proof.** GCL grounds some text in interventions, but it does not validate every natural-language assertion as a complete explanation. |
| Feature decomposition beyond raw neurons | GCL audits selected neuron sums/paths; no general sparse feature dictionary is produced by the audited GPT-2 trace. | Cunningham et al.'s sparse autoencoders learn feature directions and report finer causal localization on GPT-2 IOI [R22]; Anthropic uses cross-layer transcoders [R20]. | **Important prior art.** GCL's selected neuron/path representation is not a unique solution to polysemanticity or superposition. |
| Cross-prompt activation transfer | 744 unordered factual pairs / 1,488 directions; fixed-text token alignment; same frozen paths; restore and compare answer-sequence likelihood. | IIT is explicitly source-to-base interchange training; activation patching and causal abstraction formalize related transfers; ROME uses corruption/restoration. | **Operator established.** No reviewed source establishes the same 744-pair protocol; possible reproducible evaluation contribution, not a new transplant mechanism. |
| Counterfactual factual transfer | Directional donor-answer likelihood improves in 985/1,488 directions; transfer contrasts are positive in 462/744 A→B and 394/744 B→A. | Interchange interventions and causal abstraction are direct methodological prior art; ROME evaluates counterfactual edits. | **Empirical contribution is bounded.** Bidirectional transfer is asymmetric and not universal; teacher-forced likelihood movement is not necessarily a greedy answer switch or a sufficient circuit. |
| Necessity | Ablation lowers answer likelihood for 44/45 facts, but strictly changes correct baseline greedy prediction for 3/45. | Causal tracing/ablation, causal scrubbing, circuit faithfulness/completeness tests. | **Likelihood influence is common; strict behavioral necessity is rare.** Do not use the 44/45 likelihood result as 44/45 strict necessity. |
| Sufficiency | Full-path transplant measures donor-contrast changes; reports explicitly do not claim a complete sufficient circuit. | Causal scrubbing and causal-abstraction evaluations can test behavior preservation under a stated abstraction; circuits are commonly evaluated for sufficiency/completeness. | **Not established for GCL's discovered factual paths.** Positive logit/likelihood shift is not full prediction sufficiency. |
| Specificity vs controls | Autoregressive strict specificity: 0/50 cases pass the all-step gate. Transfer: valid magnitude-matched controls only for 38/1,488 directions; 37/38 pass the frozen rule. | ACDC uses recovery metrics; circuit papers use matched, corrupted, ablated or resampled baselines; ScrubID highlights identifiability-aware auditing. | **Limited local evidence only.** The 37/38 positive subset is not general path specificity; 1,450/1,488 directions lack valid magnitude-matched comparisons. |
| Interaction/redundancy | Group effect minus component effects measured for 600 token steps. The trace reports additive/overlap/synergy categories under a fixed rule. | Circuit interactions, mediation and causal abstraction are established areas. | **Measurement implemented; mechanism labels remain interpretations.** Nonadditivity alone does not establish redundancy, synergy, or completeness. |
| Identifiability | `identifiability_verdict` reports rank, duplicate/collinear, cancellation and weak-channel findings; source parameters can be aligned post hoc to a frozen recovered fit. | Sussmann/Fefferman provide foundational reconstruction/identifiability work; ScrubID proposes circuit-identifiability audit; parameter symmetries are well-known. | **Diagnostics exist; general uniqueness is not established.** Synthetic verdict tests and post-hoc source matching do not prove a unique real-model decomposition. |
| Oracle-only function recovery | Blind solver queries a scalar-output oracle to fit selected SwiGLU unit sums. Selected 2 cases pass; stricter randomized 16-atom court passes 1/6. | Jagielski et al. directly extract restricted two-layer ReLU networks; model stealing/knockoff work recovers function approximations; mathematical reconstruction predates GCL. | **Distinct target/application, not proven novel algorithm.** GCL targets selected 3,072D/4,096D SwiGLU functions; solver is told activation family/count/rank, and test generalization is weak under the strict randomized court. |
| Neural-network decompilation | No end-to-end full transformer/block reconstruction is implemented or validated. | Shallow-network extraction, task-specific circuit reconstruction, feature-based attribution graphs and model extraction each solve narrower tasks. | **Claim unsupported if interpreted as complete neural decompilation.** Current terms should specify either instrumented path analysis or selected-function recovery. |
| OOD robustness | GPT-2 OOD prompt replay passes 13/30 paraphrases across 2/5 facts; matched standard profile 30/30. | Prompt-generalization tests occur in ROME/circuit work; model behavior varies with prompts. | **The present OOD pilot fails its overall gate.** It is diagnostic evidence, not general semantic robustness. |
| Statistical analysis | Counterfactual transfer uses fact-endpoint cluster bootstrap and BH correction; only families with enough independent facts support inference. | Statistical circuit validation practices vary; causal abstraction supplies a framework rather than one mandatory estimator. | **Useful reproducibility practice.** Small two-fact relation families remain descriptive; overlapping pairs are not independent samples. |
| Independent verification | GPT-2 transfer verifier checks source-derived pair alignment, raw measurements, statistics and optional model replay. Trace and OOD lanes have their own verifiers. | Many public research repositories provide tests/reproduction scripts; independent implementation is less common than same-stack checks. | **Engineering strength with a boundary.** Verifiers improve auditability but are not all independently implemented solvers; the blind decompiler source-alignment verifier reuses GCL code. |
| Model-family portability | Path-finder adapters list GPT-2, GPT-NeoX/Pythia, LLaMA SwiGLU and Mistral SwiGLU. | TransformerLens and other libraries support multiple open architectures, subject to implementation coverage. | **Adapter coverage, not end-to-end parity.** The GPT-2 trace/transfer claims do not automatically transfer to every adapter. |

## Conclusions

1. Most GCL capabilities in the instrumented reader are **established methods integrated into a reproducible repository workflow**.
2. The 744-pair dataset/protocol and 50-case autoregressive artifacts are the clearest potential empirical contribution. Their novelty is the specific protocol and evidence package, not activation patching itself.
3. GCL's oracle-only selected SwiGLU-function recovery is its most distinct technical application in the reviewed set. The currently available strict randomized result (1/6 pass) and disclosed family/order assumptions prevent claims of robust general-purpose decompilation.
4. Neither activation access, a path effect, a successful transplant, nor a natural-language explanation proves a complete or uniquely identified computation.
