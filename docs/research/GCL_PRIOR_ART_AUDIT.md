# Genetic-Code-Lab: prior-art and technical differentiation audit

**Evidence cutoff:** 2026-10-30  
**Scope:** source-grounded audit of the existing repository and public research. This is not an implementation proposal for a new solver, nor a new benchmark run.

## Executive finding

GCL currently contains two materially different research tracks:

1. **Instrumented mechanistic analysis of open transformer models.** It loads model weights, captures internal tensors with hooks, selects a constrained ordered path, runs ablations/restorations, and measures prompt-specific effects. The GPT-2 trace and transfer experiments are white-box/instrumented evidence.
2. **Oracle-only recovery of selected SwiGLU functions.** A separate solver queries a scalar-valued oracle and fits an explicit sum of SwiGLU atoms. It is a real black-box function-recovery experiment, but its tested solver is told the activation family, atom count/rank, and input dimension; the oracle readiness metadata exposes `unitCount`. Its strict randomized 16-atom court passes only 1 of 6 cases.

The first track is a substantial, reproducible integration of established mechanistic-interpretability methods. The second is a distinctive application of black-box function extraction to selected high-dimensional SwiGLU functions, but the available evidence does not establish a new general extraction algorithm or a neural decompiler for whole transformer blocks/models. No reviewed source proves the specific 744-pair GPT-2 dataset/protocol has already been published; that is a possible reproducible evaluation contribution, not a new activation-transplant operator.

**Strongest supported contribution:** a repository-backed, independently replayable dataset/protocol that connects frozen ordered paths to token-level GPT-2 traces and broad counterfactual prompt-pair transfer measurements, alongside a separate oracle-only selected-function reconstruction harness. The contribution is integration and reproducible empirical scope; algorithmic novelty is unestablished.

## Evidence rules

- **Implementation evidence** means source code directly inspected in this repository.
- **Empirical evidence** means an existing machine-readable result and its associated report/verifier. An artifact's presence alone is not treated as a pass.
- **Prior art** means an original paper, official publication record, official method page, or author-maintained repository linked below.
- **Inference** is labeled as such. “No matching publication found” is limited to the sources checked; it is not proof that none exists.
- White-box tracing, instrumented causal interventions, and an oracle-only solver are not interchangeable access modes.

## Public prior art and technical comparison

### 1. Black-box model/function extraction and identifiability

- **Jagielski et al., USENIX Security 2020 [R1].** Direct extraction of a restricted two-layer fully connected ReLU model from prediction-oracle access is established prior art. This is not an extraction method for real Llama/Mistral SwiGLU units, but it rules out claims that black-box neural-network extraction itself is new. Their paper distinguishes prediction accuracy, fidelity/function equivalence and exact parameter recovery; symmetries mean parameter identity is not always identifiable.
- **Tramèr et al., USENIX Security 2016 [R2], and Knockoff Nets [R3].** Prediction APIs can be exploited to build high-accuracy/fidelity substitutes. This is functionality stealing or model imitation, not recovery of a target transformer's neurons or causal computation.
- **Fefferman [R4] and Sussmann [R5].** Mathematical reconstruction and parameter-identifiability results predate modern mechanistic interpretability. They are not turnkey transformer extraction systems; conditions and equivalence classes matter.
- **Timing/side-channel extraction [R6, R7].** These use additional leakage or privileged execution channels and target different model classes. They are not direct prediction-only comparators.
- **Active subspaces [R8].** Discover influential directions/low-dimensional surrogates, not a target model's hidden units or computational graph.

GCL's exact test target—scalar-output queries to selected, real, high-dimensional Llama/Mistral SwiGLU functions—is materially different from the shallow ReLU extraction experiments reviewed. No direct matching published result was found in the sources checked. This supports a **potential application/evaluation distinction**, not a proven new algorithm.

### 2. Factual localization and causal interventions

- **ROME/causal tracing [R9].** Corrupt-and-restore interventions localize transformer states involved in factual recall; ROME edits a middle-layer feed-forward computation. It is close prior art for causal factual localization and counterfactual editing, though not the exact GCL all-pairs transplant protocol.
- **Knowledge Neurons [R10].** Identifies and edits/erases relational factual activations in BERT cloze tasks. It establishes neuron-level factual localization/intervention in a bounded setting.
- **Interchange Intervention Training (IIT) [R11] and Causal Abstraction [R12].** The source-to-base replacement of an aligned neural representation is an interchange/activation patching intervention. Causal abstraction formalizes this family alongside causal tracing, mediation, patching and causal scrubbing. A GCL activation transplant is therefore not a new intervention operator just because it is applied to frozen paths or facts.
- **Circuit discovery and attribution patching [R13, R14].** ACDC searches task circuits in model computational graphs using activation-patching criteria; EAP approximates edge effects and ranks/prunes graph edges. Both are prior art for automated circuit localization. Neither is whole-model decompilation.
- **Causal scrubbing [R15].** Hypothesis-conditioned resampling tests whether a proposed abstraction preserves behavior. It is a stronger hypothesis-validation framing than a lone donor patch; its public source is a research post, not a peer-reviewed proceedings paper.
- **ScrubID [R16].** A public 2026 report/artifact proposes identifiability-aware circuit auditing. The repository's self-description is not evidence of conference acceptance; the review found no corresponding arXiv/proceedings record. Its results are author-reported and were not reproduced here.

### 3. Tracing, reconstruction and explanation systems

- **GPT-2 small IOI circuit [R17].** A detailed task-specific circuit reconstruction with component-level interventions, faithfulness, completeness and minimality evaluation is established white-box mechanistic research.
- **TransformerLens [R18].** An open analysis library exposes model weights, cached activations and activation editing. It is enabling infrastructure, not itself a unique circuit discovery algorithm.
- **OpenAI neuron-explanation release [R19].** Its official research page is relevant prior art for LM-generated neuron explanations. The page returned HTTP 403 to this audit's fetcher, so its fine-grained reported methods/results are not used as evidence here. Even an explanation/simulation score would not establish causal correctness or full computational recovery.
- **Sparse autoencoders [R22].** Cunningham et al. learn interpretable feature directions and report finer causal feature localization on indirect-object identification. This is an important feature-level decomposition precedent, but it does not recover the target's original neuron parameters or reconstruct a complete model.
- **Anthropic Circuit Tracing [R20].** Cross-layer transcoders/replacement models and prompt-specific attribution graphs pursue computation-level explanations, followed by interventions. The official methods article reports replacement-model output agreement around 50% of cases and discusses fixed-attention, approximation and graph limitations. This is a stronger prior for feature-level computation graphs than raw neuron labels, but it is instrumented white-box analysis, not oracle recovery of original weights.
- **HyVE/AgenticInterpBench [R21].** An agentic hypothesis/validation/explanation workflow for circuits already localized, assessed on 84 semi-synthetic circuits with 163 component annotations and a Llama arithmetic case study. It targets explanation after localization, not discovering GCL's paths or testing the same transfer protocol. The article reports validation-loop reliability limits.

## Counterfactual-transfer interpretation

The GCL transfer runner uses exact prompt-template alignment and patches the donor's frozen path activations into the recipient at aligned positions. Methodologically, this is a source-to-base interchange intervention (IIT/activation-patching family). ROME's clean/corrupt restoration and related causal-tracing work are adjacent, but not identical in purpose or outcome metric.

The reviewed public literature did **not** establish that the exact GCL combination—744 same-family fact pairs, frozen discovered ordered paths, bidirectional teacher-forced answer-likelihood contrasts, necessity/restoration, 100 structural controls per direction and endpoint-cluster statistics—has already been published. That supports describing the specific **evaluation artifact/protocol** as a GCL study, subject to reproducibility and comparison boundaries. It does not support claiming a new causal operator, universal circuit transfer, or a uniquely sufficient circuit.

## Baseline compatibility and execution

No baseline numbers were generated in this audit. A fair comparison would require the same exact GPT-2 checkpoint/tokenizer, original prompts and target answer sequences, intervention sites, causal statistic, control construction, and independent-fact unit of analysis. The methods have incompatible native assumptions:

| Baseline | Compatibility assessment | Why no fair reproduction was run |
|---|---|---|
| ROME causal tracing | Related causal localization, but not the same fixed-path, all-pairs teacher-forced transplant outcome | Published tasks/checkpoints and corruption/restore metrics differ; matching the task would require an explicit adaptation and frozen protocol. |
| Knowledge Neurons | Same broad factual-localization theme | BERT masked-LM cloze setup and attribution/editing are not GPT-2 autoregressive answer-sequence transfer. |
| IIT / causal abstraction | Conceptual and formal framework | IIT trains alignments; causal abstraction is not a single executable baseline with the same metrics. |
| ACDC / EAP | Potential graph-localization comparators | They require graph/edge definitions and task-specific localization criteria, rather than evaluating an already-frozen ordered path across all fact pairs. `transformer_lens`, `acdc`, and associated libraries are not installed in the current Python environment. |
| Causal scrubbing / ScrubID | Hypothesis validation / identifiability audit | Different graph/hypothesis and resampling semantics; no direct compatible harness or dataset. `causal_scrubbing` is not installed; ScrubID is a report/artifact, not an installed baseline. |
| HyVE | Circuit explanation, not discovery or transfer | Requires a localized circuit and evaluates explanation labels/task behavior on its own benchmark, not GCL's token-likelihood transfer metric. |
| Circuit Tracing | Computation graph explanation for other model/tooling setup | Claude 3.5 Haiku, transcoder replacement, and attribution-graph outcomes do not align with the local GPT-2 intervention protocol. |

The following baseline packages were checked without installation and were unavailable: `transformer_lens`, `pyvene`, `acdc`, `causal_scrubbing`, `nnsight`, `baukit`, `sae_lens`. This is an environment observation, not a claim that the methods cannot be implemented or adapted. No results were invented or compared across incompatible metrics.

## Capability gap and recommended direction

GCL can now inspect real instrumented GPT-2 computations and recover selected SwiGLU functions from oracle calls. The critical gap for a genuine decompiler is not “more patching” or a new renamed path finder: it is **blind structure discovery under realistic model inputs**. The isolated SwiGLU harness tells the solver the function family and atom budget; the oracle reports `unitCount`; the strict solver samples Gaussian inputs; and the randomized strict court passes 1/6 cases. Thus the current black-box evidence tests recovery under a strong structural prior, not discovery of an unknown internal computation.

The next defensible direction is one sealed evaluation: **unknown-order, real-activation-distribution function recovery for selected SwiGLU blocks**, using no solver access to source weights/hooks/atom count and a post-fit witness kept outside the solver. Keep function equivalence, canonical atom correspondence, and uniqueness as separate outcomes. See [GCL_NEXT_DEVELOPMENT_DIRECTION.md](GCL_NEXT_DEVELOPMENT_DIRECTION.md) for a bounded acceptance proposal. This is a research direction, not a claim that the repository already implements it or that no prior work exists.
