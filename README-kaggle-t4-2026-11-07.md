# Kaggle T4 replay evidence: blind SwiGLU oracle-only lanes (2026-11-07)

Headless Kaggle kernel `kuglipista/gcl-swiglu-lane` re-ran the recorded
blind-SwiGLU oracle-only recovery lanes on a free Tesla T4 session and added
new evidence twice on the same day: kernel v3 added the third model family
(Qwen2.5-7B 3584D), and kernel v5 added lane E, the recorded 16-unit block
recovery (16 atoms, activeRank 32) — the largest block replayed on this lane.
The solver reconstructed explicit SwiGLU atoms for real neural blocks from
`f(x)`-only oracle access — no solver access to weights, hooks, or source
unit IDs.

Kernel v5 re-ran lanes A–D before lane E as a regression check and reproduced
the kernel-v3 numbers **bit-for-bit** (same metrics to the last digit, same
oracle-call budgets), which additionally demonstrates cross-run determinism
of the T4 replay itself.

## What ran

- **A** — Mistral-7B-Instruct v0.3 (unsloth 4-bit, 4096D) randomized 2-block
  8-unit forward-coordinate sweep, 2 cases (layer 1 and layer 19, 8 recorded
  units each, 8 atoms).
- **B** — LLaMA-3.2-3B-Instruct (unsloth 4-bit, 3072D) randomized 8-unit
  layer sweep, 8 single-unit cases across layers 0–25 (2-probe coordinate
  mode).
- **C** — LLaMA-3.2-3B 3072D layer-20 deterministic 6-unit recovery
  (units 0, 17, 123, 456, 789, 1024; 6 atoms).
- **D** — Qwen2.5-7B-Instruct (unsloth 4-bit, 3584D) randomized 8-unit layer
  sweep, 8 single-unit cases across layers 0–25 (2-probe coordinate mode);
  enabled by patch 0004 (qwen2 `model_type` allowlist in the selected-unit
  blind SwiGLU oracle).
- **E** — LLaMA-3.2-3B 3072D layer-1 deterministic 16-unit block recovery
  (units 27, 57, 413, 500, 1607, 1970, 2215, 2529, 2847, 3530, 3786, 4033,
  4236, 4906, 7283, 7720; 16 atoms, activeRank 32, forward-coordinate mode
  with the full recorded adaptive solver environment). All 16 recovered atoms
  pair one-to-one with source units above the 0.99 joint-cosine bar
  (min joint cosine 0.9999809819).

## Access invariants (every report, 23 directories)

- `solverAccess: "oracle-only"`; `weightsUsedBySolver: false`;
  `hooksUsedBySolver: false`; `sourceIdsUsedBySolver: false`;
  `postHocWitnessOnly: true`; per-case reports additionally record

- The solver process receives only `f(x)` batch outputs; source weights are
  requested only after recovery is frozen, for post-hoc witness alignment.

## Claim boundary

These sweeps prove selected real local Mistral/LLaMA/Qwen-family SwiGLU unit
or small-unit-block outputs can be recovered as blind oracle-only explicit
SwiGLU atoms under the recorded case budgets. They do not prove full FFN
extraction, all-channel decompilation of any dimension, exhaustive LLM
circuit recovery, or semantic original-neuron identity from output-only
access.

## Related work

The closest published result is Shi & Fu, "Cryptanalytic Extraction of
Isolated Bias-Free GLU Feed-Forward Blocks by Antipodal Separation"
(arXiv:2608.06631, August 2026): forward-query recovery of isolated bias-free
GLU blocks, including thousands-of-units and full-block demonstrations on
Qwen3-0.6B, LLaMA-3.2-1B, and Gemma-3-1B. GCL's lane differs in model scale
and emphasis (7B-class models, quantized providers, cross-platform replay,
access auditing) and has not demonstrated full-block recovery. See
`docs/related-work-blind-swiglu-extraction.md` for the full positioning and
the open head-to-head protocol.
